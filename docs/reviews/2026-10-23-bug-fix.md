## Minor

### 🟡 queryIds mixes string IDs and ObjectIds in the same array, `backend/src/routes/admin.ts:L298-L312`

**Problem**: `queryIds` starts as `Array.from(userIds)` (plain strings) then pushes `new ObjectId(id)`
into the same array. The query then runs `{ id: { $in: queryIds } }` against Better Auth user
documents where the `id` field is a plain string. MongoDB will not match a string field against an
ObjectId value, so the ObjectId entries on that leg are noise. No wrong results but the intent is
obscured and the query does redundant work.

**Fix**: Split into two typed arrays, one for `_id` (ObjectId) and one for `id` (string), and pass each
to its own query leg. Seven lines; nothing else changes.

**If we skip it**: No incorrect data. Low risk, just wasted comparison work and confusing code.

## Strengths

  to newest, caches both without over-caching misses.
- Fail-closed token cleanup on JWT minting failure is precisely scoped: deletes only newly-minted
  tokens by plain and hashed form, marks only the active family slot as revoked.
- Bounded user lookup in the logs endpoint correctly short-circuits the query entirely when there are
  no sessions, preventing a full scan on an empty log set.
- Removing all three write-only Redis token family cache functions eliminates network round trips on
  every rotation with zero behavioral change (no reader ever called `getCachedTokenFamilyStatus`).
