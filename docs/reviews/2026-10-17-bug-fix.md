## Minor
### 🟡 Single process in memory mutex on Next.js consumer, `test/next-app/src/lib/oauth.ts:85`
**Problem**: The Next.js consumer application coordinates token refreshes using an in memory JavaScript Map of promises.
**Why it matters**: In serverless, cluster mode, or multi container deployments, two separate processes handling requests for the same session will each execute token refresh independently. The IdP grace window prevents family revocation, but the losing process receives HTTP 400 invalid grant and requires reauthentication.
**Suggested fix**: For multi process deployments, consumer applications should configure distributed session storage such as Redis or a shared database to coordinate token refresh across instances.
