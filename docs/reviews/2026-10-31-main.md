## Summary
This change set improves platform sign in isolation from private app cookie state and fixes two factor continuation during OAuth authorization. Key improvements include stripping prompt parameters to prevent redirect loops, removing eager session resumption on two factor screens, and adding a disposable in memory database for private app isolation tests. However, the change introduces a localhost binding default in the production node server bundle that breaks container deployments, carries a logic flaw that triggers premature lockout on a single mistyped two factor code, and leaves an untracked helper script with backdoor test endpoints in the repository.

## Blockers
### 🔴 Production node server binds to loopback address by default, `backend/src/node-server.ts:14`
**Problem**: The entry point configures `hostname: process.env.HOST || "127.0.0.1"`. In `@hono/node-server`, omitting `hostname` defaults to all network interfaces (`0.0.0.0`). Defaulting to `127.0.0.1` binds exclusively to the local loopback interface.
**Why it matters**: In container platforms like Docker, Railway, Fly.io, Cloud Run, and Render where `node-server.ts` is deployed via `npm run build:node`, external requests and ingress health checks fail to connect unless `HOST=0.0.0.0` is explicitly set. This also violates the project rule prohibiting localhost fallbacks in production server configurations.
**Suggested fix**: Bind to all network interfaces by defaulting to `"0.0.0.0"` when `process.env.HOST` is unset, or omit the `hostname` property entirely so `@hono/node-server` defaults to all interfaces.

## Major
### 🟠 Premature session expiration redirect on single mistyped two factor code, `frontend/pages/admin/AdminTwoFactor.tsx:43`
**Problem**: The verification failure handler evaluates `if (nextFail >= 3 || verifyRes.error.status === 401 || verifyRes.error.status === 403 || errMsg.toLowerCase().includes('session'))`. The Better Auth two factor verification endpoint returns HTTP status 401 for an incorrect code. Because `verifyRes.error.status === 401` evaluates to true on every invalid attempt, this branch executes immediately on the first attempt. The same pattern appears in `frontend/pages/TwoFactor.tsx:43`.
**Why it matters**: Any user or administrator who mistypes a single digit of their code is ejected immediately to the login page with a misleading session expired message. The intended retry threshold of three attempts is dead code.
**Suggested fix**: Remove `verifyRes.error.status === 401` from the session expired guard. Rely on the attempt counter reaching three attempts before redirecting, and check specific error messages or error codes when identifying genuinely expired sessions.

### 🟠 Untracked test server script contains credentials and backdoor endpoints, `backend/scripts/run-browser-verification-servers.ts:11`
**Problem**: The untracked script hardcodes an author specific agent scratch directory on line 11 and mounts unauthenticated HTTP endpoints `/test-api/creds`, `/test-api/totp`, and `/test-api/reset-ratelimit` on the frontend gateway server on lines 235 to 254.
**Why it matters**: These diagnostic endpoints return plaintext administrator passwords, secrets, and generate valid one time passcodes on demand. If accidentally committed, executed in staging, or deployed, platform security is completely compromised.
**Suggested fix**: Remove the untracked file from the repository or move it to a private local scratch directory outside the repository source tree. If kept as a permanent test script, remove the diagnostic backdoor endpoints and replace hardcoded directory paths with dynamic temporary paths.

### 🟠 Continuous integration security test target drifts from test runner script, `backend/package.json:60`
**Problem**: In `backend/package.json`, `test:all-security` is an inline command string that has drifted from `backend/scripts/run-all-security.ts`. It omits five security test suites: `consumer-mfa-continuation.test.ts`, `adversarial-role-tampering.test.ts`, `account-switch-e2e.test.ts`, `nosql-injection-boundary.test.ts`, and `private-app-login-isolation.test.ts`. While `private-app-login-isolation` was added as a separate step in `.github/workflows/ci.yml`, `consumer-mfa-continuation.test.ts` and the other omitted suites do not run in continuous integration.
**Why it matters**: Critical security regressions, including the new consumer two factor continuation test suite and NoSQL injection boundary checks, are not verified in continuous integration.
**Suggested fix**: Update `test:all-security` in `backend/package.json` to execute `tsx scripts/run-all-security.ts`, ensuring all security test suites run in continuous integration without duplicating the test file list.

## Minor
### 🟡 Platform sign in detection does not handle absolute callback URLs, `backend/src/routes/auth.ts:339`
**Problem**: Function `extractClientId` checks `callbackPath.startsWith("/admin")` and `callbackPath.startsWith("/api/admin")`. If a caller passes an absolute URL like `https://auth.example.com/admin`, `callbackPath` starts with `http` rather than `/admin`.
**Why it matters**: Platform sign in detection fails when given absolute URLs, causing the server to fall back to stale cookies from prior private app OAuth sessions.
**Suggested fix**: Normalize the callback URL using `new URL(rawCallback, "http://localhost").pathname` before testing the path prefix.

### 🟡 Duplicated prompt parameter deletion logic, `frontend/pages/SignIn.tsx:60`
**Problem**: Lines 60, 144, and 208 duplicate `const oauthParams = new URLSearchParams(searchParams); oauthParams.delete('prompt');`, and recalculate `safeDest` instead of reusing `callbackURL`.
**Why it matters**: Code duplication creates maintenance overhead and increases the chance of inconsistent redirect parameters in future modifications.
**Suggested fix**: Centralize OAuth destination formatting into a single helper function or reuse the sanitized `callbackURL` value.

## Strengths
- Stripping the prompt query parameter on OAuth resume prevents infinite redirect loops between authorize and sign in.
- Removing the automatic session resume effect in `frontend/pages/TwoFactor.tsx` closes an authentication bypass window and ensures two factor verification must execute.
- Changing two factor inputs from `type="number"` to `type="text"` with numeric input mode fixes leading zero truncation.
- Using a guaranteed disposable in memory Mongo server ensures complete test isolation in `private-app-login-isolation.test.ts`.

## Test coverage
The security test suites are thorough and well structured. `private-app-login-isolation.test.ts` covers 10 isolation scenarios, and `consumer-mfa-continuation.test.ts` covers 8 two factor continuation scenarios. All suites pass when executed. The primary gap is configuration: `consumer-mfa-continuation.test.ts` is omitted from `backend/package.json` and continuous integration workflows.
