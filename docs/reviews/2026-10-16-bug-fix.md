## Resolution of Review Findings

### 1. Refresh Failure Safety and Elimination of Credential Resurrection
* **Issue**: The previous rollback logic on token minting failure executed updates with `{ upsert: true }`, creating a vulnerability where consumed, revoked, or expired refresh tokens could be resurrected with fresh expiration dates.
* **Resolution**: Removed all `{ upsert: true }` clauses and backward rollback restoration logic in `backend/src/routes/auth.ts`.
* **Forward Only Policy**: When RS256 token minting fails during token refresh, the token family is immediately marked as revoked (`status: "revoked"`). The newly generated unminted credential record is purged from MongoDB. The previous credential remains consumed. No credential document is ever recreated, unrevoked, or extended in lifetime.
* **Deterministic Behavior**: The endpoint returns HTTP 500 `server_error` without opaque fallback. Any subsequent presentation of either the consumed root or the failed candidate is rejected with HTTP 401 `invalid_grant`.
* **Automated Regression**: Added comprehensive unit test coverage in `backend/tests/unit/runtime-resilience.test.ts` (Tests 6 and 7) validating forward only family revocation, unminted credential cleanup, single use code retention, concurrent administrator revocation barriers, and competing rotation single winner semantics.

### 2. Real IdP Process Restart Test Retaining Disposable Database
* **Issue**: Previous restart tests only invoked in memory cache eviction functions rather than testing real OS process restart semantics.
* **Resolution**: Created `backend/tests/e2e/idp-process-restart.test.ts` registered as `npm run test:process-restart`.
* **Test Architecture**: Boots a disposable `MongoMemoryServer` instance that persists across process lifetimes. Spawns an initial IdP child process via OS `spawn` on an available loopback TCP port. Issues RS256 access and refresh tokens. Terminates the initial IdP child process using process group `SIGKILL`. Spawns a fresh IdP child process pointing to the retained MongoDB instance.
* **Verifications**: Validates that pre restart RS256 JWTs verify against restarted IdP JWKS public keys, pre restart refresh tokens rotate cleanly into new RS256 access tokens on the restarted IdP, and user profile retrieval functions normally across the restart boundary.

### 3. Multi Process Network Consumer End to End Coverage
* **Issue**: The original consumer test suite exercised Hono `app.request()` in process, without live TCP servers, real browser cookie jars, or network isolation.
* **Resolution**:
  * Explicitly labeled `backend/tests/e2e/local-consumer-e2e.test.ts` as an in process protocol test suite to ensure transparent and honest reporting.
  * Created `backend/tests/e2e/network-consumer-e2e.test.ts` registered as `npm run test:network-consumer-e2e`.
* **Live Network Architecture**: Simultaneously runs three independent child processes on distinct loopback TCP ports: the IdP node server, the real Next.js application (`next start`), and the real React Express backend server.
* **Verified Live Network Flows**:
  * Next.js live cookie session lifecycle: `/api/auth/login` redirect, PKCE cookie jar management, authorization code exchange, HttpOnly session cookie issuance, and protected `/api/secure-data` access.
  * Express live cookie session lifecycle: `/auth/login` redirect, code exchange via HTTP Basic client authentication, HttpOnly `app_session` cookie issuance, and protected `/api/secure-telemetry` access.
  * Cross application audience isolation: Next.js access token presented to Express is rejected with 401 or 403 due to audience mismatch. Express access token presented to Next.js is rejected with 401 due to audience mismatch.
  * Network refresh token rotation and auto refresh: Refreshing tokens over HTTP rotates credentials and updates session cookies. Next.js auto refreshes expired sessions transparently when accessing protected routes. Revoked refresh tokens trigger cookie clearance and return deterministic `recovery_flow: "reauthenticate"`.
  * Account switching: Initiating login for a second user replaces active session cookies and reflects the updated user identity.
  * Private application tenant isolation: Assigned user receives authorization code. Unassigned user is rejected with `error=access_denied`.

### 4. Cross Process Consumer Refresh Race Coordination
* **Issue**: Single process in memory promise deduplication does not protect multiple consumer processes sharing the same session from racing on token refresh.
* **Resolution**: Added `SharedSessionStore` contract to `test/react-express-app/backend/src/middleware/auth.ts` and created `backend/tests/e2e/cross-process-refresh.test.ts` registered as `npm run test:cross-process-refresh`.
* **Race Semantics**: Launches two separate consumer processes sharing an active session and executes a concurrent refresh race against the IdP.
* **Guarantees**: Exactly one process wins the rotation race and receives fresh RS256 credentials. The losing process receives HTTP 401 with `recovery_flow: "reauthenticate"` without triggering token family cascade revocation. Winning credentials authenticate successfully on both consumer processes.

### 5. Local Zero Dependency Security Test Runner
* **Issue**: Running the fourteen security test suites locally previously failed because tests depended on an external MongoDB service.
* **Resolution**: Created `backend/scripts/run-all-security.ts` registered as `npm run test:all-security:local`.
* **Test Architecture**: Spins up a disposable in memory `MongoMemoryServer`, exports necessary configuration, and executes all fourteen security test suites sequentially with zero external Docker dependencies.
* **Result**: All fourteen suites pass with zero failures.
