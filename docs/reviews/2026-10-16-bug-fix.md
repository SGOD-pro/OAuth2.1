## Detailed Findings & Verifications

### 1. Controlled server_error on Minting Failure
- `backend/src/routes/auth.ts`: Both authorization code and refresh token endpoints trap `mintJwtAccessToken` failures. State cleanup restores family `activeTokenHash`, clears `rotating`, removes unminted access and refresh tokens (matching raw and base64url hash representations), and returns HTTP 500 with `{ error: "server_error", error_description: "Failed to mint RS256 access token" }`.
- Verified in `backend/tests/unit/runtime-resilience.test.ts` Test 6.

### 2. Signing Key and JWKS Serialization
- Private keys generated by `getIdpSigningKey` are encrypted via `symmetricEncrypt` and JSON-stringified before insertion into MongoDB `jwks` collection, ensuring full compatibility with Better Auth's `resolveSigningKey` (`data: JSON.parse(key.privateKey)`).
- Minted RS256 JWT access tokens explicitly set a unique `jti` claim (`crypto.randomUUID()`) adhering to RFC 9068 Section 2.2 and guaranteeing global token uniqueness.

### 3. Grace Window & Replay Invariants (Spec 0002 AC-5, AC-6)
- In `backend/src/db/state.ts`, `verifyAndRotateTokenFamily` checks `doc.rotatedAt || doc.updatedAt` to evaluate the 2000ms grace window.
- Presentation of a consumed refresh token within the grace window returns `400 invalid_grant` without revoking the active family (AC-5).
- Presentation outside the grace window cascade-revokes the family (`status: "revoked"`) and purges scoped active tokens (AC-6).
- Subsequent use of child tokens from a revoked family returns `401 invalid_grant`.

### 4. Consumer Refresh Coordination
- In-flight Promise deduplication mutex (`coordinateTokenRefresh`) prevents duplicate network calls during concurrent refresh triggers in consumers.
- Implemented in `test/react-express-app/backend/src/middleware/auth.ts` and `test/next-app/src/lib/oauth.ts`.
